四个故事，讲清四个词

老王开了一家水果店。他装了一个传菜口、一个万能插排、发了一套小卡片、 又给实习生套上了缰绳——这四个动作，正好对应 API、MCP、Skill、Harness。

API · 传菜口 MCP · 万能插排 Skill · 作业卡片 Harness · 缰绳与监控
① API ② MCP ③ Skill ④ Harness 总结对比
故事一

API老王的“传菜口”

老王开了一家水果店，既做网店，也做线下。网店每来一单，店员就把订单信息手抄到进销存本子上： 谁买的、几斤苹果、送到哪、付了多少钱。刚开始单少还行，后来单子一多， 抄错地址、漏记数量、重复记账全来了。店员每天加班，老王还赔了不少钱。

后来老王装了一个“传菜口”：网店不直接把单子喊给店员听，而是按一个固定格式把订单递进窗口—— 第一行写订单号，第二行写商品，第三行写地址，第四行写金额。进销存那边也按固定格式接单， 接到就自动记账。店员不用再抄，两个系统自己把单子传明白了。

一句话定义 API 就是这个“传菜口”。它不是 AI，也不是某个具体软件， 而是两个系统之间约定好的对接窗口：你按我的格式递，我按我的规则接。 网店和进销存本来各干各的，API 让它们能说上话。
和后面几个词的区别 API 解决的是“系统与系统之间怎么传东西”。它是最基础的连接方式， 重点在“两个系统能通话”。
故事二

MCP老王的“万能插排”

老王的生意越做越大，网店之外又接了外卖平台、团购平台、直播带货、财务软件、客服系统。 每接一个新平台，技术人员就要重新拉一根“专线”：外卖平台一套对接，团购平台又一套， 直播后台再来一套。每套对接都要写代码、调格式、测半天，电工费比卖水果赚的还多。

更麻烦的是，老王后来想换一个更聪明的 AI 来帮忙管这些系统。结果技术人员说： 换 AI 可以，但每个平台都得重新接一遍，因为每个平台的插头都不一样。 老王一听就头大：这不等于每换一次工具，就把墙重新砸一遍吗？

于是老王装了一个“万能插排”：不管外卖、团购、直播、财务还是客服， 都按同一个标准插头插上去。AI 要调用哪个工具，就从插排上取电； 以后换 AI，也不用重新布线，插上就能用。

一句话定义 MCP 就是这个“万能插排”。它规范的不是“某个系统怎么对接”， 而是“AI 怎么用统一标准去连接外部工具和数据”。 API 是单个系统的点餐窗口，MCP 是让 AI 一次对接很多窗口的通用转接头。
和 API 的区别 API 解决“两个系统之间怎么通”；MCP 解决“AI 接很多工具时， 怎么不用每接一个就重新写一套”。API 更像单个窗口，MCP 更像统一插头标准。 它们不是互相替代，而是不同层面的连接问题。
故事三

Skill老店长的“退货小卡片”

老王店里退货最让人头疼。新店员一遇到退货就慌：先查订单还是先问原因？ 生鲜烂了是退钱还是换货？要不要补一张券？要不要叫店长？ 每个人做法不一样，有的客户被退得很满意，有的客户被气得发差评。

老店长处理退货很有一套：先查订单时间，再问清楚是质量问题还是口味问题， 生鲜类优先退款不换货，老客户补一张小额券，大额退款必须叫店长。 可问题是，老店长只有一个，新店员学不会，老店长一休假，退货就乱套。

后来老王把老店长的做法写成一张“退货小卡片”：第一步查什么，第二步问什么， 第三步按什么规则退换补，最后输出什么记录、用什么语气跟客户说。 所有店员都照这张卡干活，新人也能干出老店长的水平。 这张卡不是某个系统，也不是插头，而是一套“遇到退货该怎么一步步做”的作业方法。

一句话定义 Skill 就是这张“作业小卡片”。它把人的经验、流程、标准和做法封装起来， 变成 AI 可以反复照着执行的能力包。AI 连上了系统，不等于知道该怎么干活； Skill 告诉它：这件事分几步、每步用什么口径、最后交什么结果。
和 MCP 的区别 MCP 管“连得上”，Skill 管“连上之后按什么章法做”。 有了万能插排，不代表店员会退货；有了 Skill，AI 才知道遇到具体任务该怎么一步步做对。
故事四

Harness给聪明实习生套上“缰绳”

老王后来招了一个特别聪明的实习生，脑子快、手脚麻利，收银、查库存、 给客户发消息一学就会。老王本来很高兴，但真让他上岗，老王睡不着了： 他会不会为了冲业绩乱打折？会不会偷偷改价格？会不会把客户电话发给别人？ 出了错谁负责？能不能查到他干了什么？大额退款他会不会自己就批了？

实习生能力很强，但老王不敢把店交给他。于是老王给他配了四样东西： 一张权限卡，最多只能打九折；一道审批，大额退款必须找店长； 一本留痕账，每笔操作都有记录；一个报警器， 发现异常价格或异常退款就自动停下来。 实习生还是那个聪明实习生，还能干活，但他跑不出老王画的圈。

一句话定义 Harness 就是这套“缰绳加监控”。它不是某个具体工具， 而是套在 AI Agent 外面的运行时治理层：什么能做、什么不能做、权限怎么管、 大额操作谁审批、每一步有没有留痕、出问题能不能回滚、成本超了能不能停。 模型再聪明，没有 Harness，组织就不敢让它真正碰业务。
和 Skill 的区别 Skill 让 AI“会做对”，Harness 让组织“敢让它持续做”。 Skill 是作业手册和能力内容，Harness 是权限、审批、审计、监控和兜底。 一个管“怎么做”，一个管“做到什么边界、出了事怎么办”。

销售自己记住一句话就够了：
API 让系统通，MCP 让 AI 接得快，Skill 让 AI 会干活，Harness 让组织敢让 AI 干活。
这四个词的区别，不在于谁更高级，而在于它们回答的是四个不同的问题。

名词 老王故事里的画面 它到底管什么 和别的词的区别
