安装与配置
全程约 3 分钟，自建服务需手动写入配置并信任
1 写入配置

在 ~/.workbuddy/mcp.json 中声明两个服务

2 信任并启用

自定义连接器列表中找到条目，点「信任」并打开开关

3 完全重启

列表仅在启动时读取，需彻底退出进程后重开

4 开始调用

用斜杠命令或自然语言发起请求

配置文件 ~/.workbuddy/mcp.json 
{
  "mcpServers": {
    "medreport": {
      "type": "streamable-http",
      "url": "https://mcp.your-domain.com/medreport",
      "headers": { "Authorization": "Bearer <TOKEN>" }
    },
    "qa": {
      "type": "streamable-http",
      "url": "https://mcp.your-domain.com/qa",
      "headers": { "Authorization": "Bearer <TOKEN>" }
    }
  }
}
使用指南
三种调用方式，按需选择
/medreport:brief 生成指定主题的医药调研简报，例如「PD-1 抑制剂 · 中国市场」
/medreport:compare 对多个竞品做适应症、机制、进度维度的横向对比
/qa:ask 提出单个问题，返回答案与引用来源，例如「什么是 IND 申报」
/mcp 查看连接状态、重新加载配置，排查连接问题的第一站
也可以直接用自然语言描述需求，例如「帮我查一下某靶点的全球在研情况」，客户端会自动选择合适的 MCP 与工具。命令名称由服务器端定义的 Prompt 决定，格式为 /服务器名:prompt。
常见问题
接入与使用过程中最高频的 6 个问题
自建的 MCP 为什么在连接器市场里搜不到？
这是设计如此，不是故障。自建或未上架官方的连接器不会进入公共市场索引，需要通过 「连接器 → 自定义连接器」 手动添加。添加完成后，它只会出现在该弹窗的 MCP 服务列表里。
保存配置后，列表里看不到新服务怎么办？
按顺序检查三点：
  • 配置文件是否位于 ~/.workbuddy/mcp.json，注意是 mcp.json 而非 .mcp.json；
  • JSON 是否合法（多余的逗号、括号不匹配都会导致整体加载失败）；
  • 是否彻底退出客户端进程后重新打开——列表只在启动时读取一次。
粘贴完 JSON，找不到「信任」按钮？
「信任」不在编辑界面里，而是针对保存后生成的服务条目。先点保存，再回到 MCP 列表，展开对应条目，信任开关在条目旁的详情中。若仍看不到，可尝试切换标签页刷新或彻底重启客户端。
调用一直超时或返回空结果？
先用 /mcp 查看连接状态。若显示已连接但调用超时，通常是服务端问题：核对 URL 是否可访问、Token 是否过期、Bearer 与密钥之间是否保留一个空格。医药调研报告的检索链路较长，首次调用可能偏慢，属正常现象。
医药调研报告的数据来源可靠吗？
报告中的每条结论都会附带来源标注（数据库名称、检索时间、文档编号）。建议在正式引用前，对关键结论回溯原文核实。该服务提供的是检索与聚合能力，不替代人工的医学判断。
两个 MCP 可以同时启用吗？会互相影响吗？
可以同时启用，二者独立运行、互不干扰。客户端会根据你的问题描述自动选择合适的服务；如果存在歧义，可以在指令中明确指定，例如以 /qa:ask 或 /medreport:brief 开头。
